# VK Chat Exporter

Веб-сервис для безопасного экспорта переписок и личных сообщений ВКонтакте в чистый текстовый формат `.txt`.

Разработан в соответствии с принципами безопасности:
- Авторизация исключительно через официальный протокол **VK OAuth 2.0 / VK ID**.
- Никакого сбора логинов, паролей, парсинга web-страниц или работы через cookies.
- Access Token и Client Secret хранятся **только на сервере** и никогда не передаются на frontend.
- Сообщения пользователей не сохраняются в долговременную базу данных и не передаются сторонним AI-сервисам.
- Прямой экспорт в чистый TXT с поддержкой кириллицы (UTF-8 BOM), корректным переносом строк и форматированием вложений.

## 🚀 1. Установка зависимостей

Убедитесь, что у вас установлен **Node.js** версии 18 или новее.

Клонируйте репозиторий и установите пакеты:

```bash
git clone https://github.com/your-username/vk-chat-exporter.git
cd vk-chat-exporter
npm install
```

---

## 💻 2. Локальный запуск проекта

1. Создайте локальный файл `.env` на основе примера:
   ```bash
   cp .env.example .env
   ```

2. Запустите сервер разработки:
   ```bash
   npm run dev
   ```
   *Или запуск напрямую через Node:*
   ```bash
   node server/server.js
   ```

3. Откройте в браузере: `http://localhost:3000`

## 🔑 3. Переменные окружения (.env)

| Переменная | Обязательна | Описание |
|------------|-------------|----------|
| `PORT` | Нет (по умолч. 3000) | Порт для запуска веб-сервера |
| `APP_URL` | Рекомендуется | Полный публичный URL вашего сервиса (например, `http://localhost:3000` или `https://my-exporter.run.app`) |
| `VK_CLIENT_ID` | Да (для прод.) | ID приложения ВКонтакте из кабинета [dev.vk.com](https://dev.vk.com) |
| `VK_CLIENT_SECRET` | Да (для прод.) | Защищённый ключ приложения из настроек VK |
| `VK_REDIRECT_URI` | Нет | Кастомный Redirect URI. По умолчанию: `${APP_URL}/api/auth/vk/callback` |
| `DEMO_MODE` | Нет (`false`) | Включение режима демонстрации с тестовыми переписками без создания приложения VK |

> ⚠️ **Важно:** Файл `.env` включён в `.gitignore` и ни при каких обстоятельствах не должен попадать в репозиторий GitHub.

## ⚙️ 4. Как настроить VK-приложение

1. Перейдите на портал разработчиков [dev.vk.com](https://dev.vk.com) и войдите в свой аккаунт.
2. Нажмите **«Создать приложение»** (или перейдите в «Мои приложения»).
3. Выберите тип приложения:
   - **Сайт (Web)** — стандартный тип для веб-сервисов с OAuth Code Flow.
   - **Standalone-приложение** — исторически предоставляло более широкий доступ к разделу `messages` для тестовых пользователей и владельца приложения.
4. В разделе **«Настройки»** приложения скопируйте:
   - **ID приложения** -> укажите в `.env` как `VK_CLIENT_ID`
   - **Защищённый ключ** -> укажите в `.env` как `VK_CLIENT_SECRET`

---

## 🔗 5. Как указать Redirect URI

В настройках вашего приложения ВКонтакте на [dev.vk.com](https://dev.vk.com):

1. В поле **«Адрес сайта»** укажите базовый URL (например, `http://localhost:3000/` или `https://your-domain.com/`).
2. В поле **«Базовый домен»** укажите домен (например, `localhost` или `your-domain.com`).
3. В поле **«Доверенный redirect URI»** добавьте:
   ```
   https://your-domain.com/api/auth/vk/callback
   ```
   *(Для локальной разработки: `http://localhost:3000/api/auth/vk/callback`)*

## 🌐 6. Деплой Backend

Проект представляет собой стандартное Node.js приложение без сложных внешних зависимостей.

### Вариант A: Render / Railway / Fly.io
1. Подключите ваш GitHub-репозиторий в панели Render / Railway.
2. Команда сборки (Build Command): `npm install`
3. Команда запуска (Start Command): `node server/server.js` (или `npm start`)
4. Задайте переменные окружения: `VK_CLIENT_ID`, `VK_CLIENT_SECRET`, `APP_URL`.

### Вариант B: Docker / Cloud Run
```dockerfile
FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci --only=production
COPY . .
EXPOSE 3000
ENV NODE_ENV=production
CMD ["node", "server/server.js"]
```

## 🔌 7. Подключение Frontend к Backend

Frontend и Backend объединены в единый стек:
- Backend на Express обслуживает статические файлы из папки `client/`.
- Все вызовы API идут по относительным путям (`/api/...`), поэтому после смены домена или деплоя на сервер **не требуется переписывать JS-код**.
- Если вы решите разместить frontend отдельно (например, на GitHub Pages или Vercel), укажите базовый URL в fetch-запросах в `client/app.js` и настройте CORS заголовки в `server/server.js`.

## ⚠️ 8. Ограничения официального VK API

Политика безопасности ВКонтакте накладывает строгие требования на работу с личными сообщениями пользователей:

1. **Ограничение метода `messages` (Ошибка 15: Access Denied):**
   - Методы `messages.getConversations` и `messages.getHistory` **недоступны** обычным сайтам по умолчанию без прохождения официальной модерации VK.
   - При попытке вызвать метод неавторизованным приложением VK возвращает ошибку:
     `{"error": {"error_code": 15, "error_msg": "Access denied: no access to call this method"}}`.
2. **Как официально получить доступ:**
   - Подать заявку на модерацию в службу поддержки разработчиков ВКонтакте с описанием сценария использования сервиса.
   - Использовать Standalone-авторизацию для аккаунта разработчика / доверенных тестировщиков приложения.
   - Либо использовать сообщения от имени сообщества (Bot API / Community Tokens), если диалоги ведутся с группой.
3. **Демо-режим в приложении:**
   - Для того чтобы разработчики, проверяющие и пользователи могли полностью оценить интерфейс, алгоритм пагинации, адаптивный просмотр и генерацию чистого TXT-файла, сервис содержит встроенный **«Демо-режим»**.
   - Демо-режим не требует ключей VK и на 100% повторяет реальный сценарий выгрузки диалогов.

## 📄 Формат экспортируемого TXT

Файл формируется в хронологическом порядке от старых к новым сообщениям:

```text
========================================================
ЭКСПОРТ ПЕРЕПИСКИ VK: Екатерина Смирнова
Дата выгрузки: 04.09.2026 21:15
Всего сообщений: 85
========================================================

[04.09.2026 21:14] Екатерина Смирнова:
Привет! Как продвигается работа над сервисом?

[04.09.2026 21:15] Александр Иванов:
Привет! Всё готово. Сообщения выгружаются в чистый TXT без лишних HTML-тегов и мусора.
[Вложение: фото]
```

- Кодировка: **UTF-8 с сигнатурой BOM**, корректно открывается в Блокноте Windows, TextEdit macOS, мобильных редакторах на Android/iOS.
- Вложения обозначаются информативными метками: `[Вложение: фото]`, `[Вложение: видео: "Название"]`, `[Вложение: голосовое сообщение (12 сек.)]`, `[Вложение: документ: "spec.pdf"]`.

## 🛡️ Безопасность

- Никакие токены не попадают в браузер пользователя (хранятся в HTTP-Only Secure Cookie в сессии на сервере).
- Защита от CSRF-атак через случайный параметр `state` при OAuth-авторизации.
- По нажатию «Выйти» серверная сессия уничтожается и cookie очищается.
